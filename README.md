# Last-Star

사용자가 첨부한 「추모 별 지도 프로토타입.html」이 디자인 기준입니다. 원본 CSS·별 데이터·타이포그래피·밤하늘·사진/소리/글 캔버스를 유지하며, 롤링페이퍼만 부가 기능으로 연결했습니다. 원본 첨부 파일은 변경하지 않았습니다.

## 개발

Node.js 22 이상에서 외부 패키지 설치 없이 실행합니다.

```sh
cd /workspace/ai
npm start
```

기본 포트는 3000, `PORT`로 변경할 수 있습니다. `npm run dev`는 자동 재시작, `npm test`는 서버 검증입니다. 현재 기본 화면은 첨부본 기반이며 `/classic`에는 이전 별도 시제품을 보존했습니다.

## 디자인 기준

- 원본의 검정 밤하늘, 중앙의 별과 이름, 하늘에 배치하는 추억 유지
- 원본의 하늘/모아보기와 사진·영상·음성·글 동작 유지
- 추가한 2단 프로필·큰 대표 사진·초록 배경·별 정보 패널 제거
- 방 안의 ‘추모 편지’ 버튼으로 아래 롤링페이퍼 이동
- 편지 영역은 원본 글꼴과 검정·흰색을 사용하며 편지지 선택은 테두리 색으로 구분
- 데스크톱 웹 우선. 모바일 추가 설계는 보류
- 향후 기능도 원본 HTML의 구성·스타일 안에 추가하고 별도 디자인으로 교체하지 않음

## 저장 및 한계

추모 편지·소개와 마지막으로 저장한 이름·별 정보는 이 브라우저의 localStorage에 보관됩니다. 이전 버전의 편지 저장 키와 호환됩니다. 이전 버전에서 보관한 소개도 복원 시 읽습니다. 사진·영상·소리와 캔버스 글은 세션 중에만 유지되며 새로고침하면 사라집니다. 계정 저장·초대·공동 작성은 시뮬레이션입니다. 브라우저 데이터 삭제 시 편지도 사라집니다.

## 출처

첨부본의 HYG v4.4 데이터와 출처 고지를 유지했습니다. 원본에 표기된 데이터 라이선스는 CC BY-SA 4.0, 출처는 https://codeberg.org/astronexus/hyg 입니다. 별 소유권이나 공식 명명 서비스가 아닙니다.

## 검증

원본 CSS 전체와 별 JSON의 동일성을 확인했습니다. Chromium 데스크톱에서 별 검색·선택, 편지 작성·색·작성자, 새로고침 복원, HTML 텍스트 안전 표시, 저장 실패 시 입력 유지, 편지 바로가기를 검증했습니다. 서버 테스트 3개를 실행합니다.

## 내용 구성

원본 밤하늘과 중앙 별을 유지한 채 ‘소개 / 생애와 이야기 / 사진·소리 / 추모글’ 탭으로 내용을 구분합니다. 소개는 편집·브라우저 저장을 지원하며 최근 편지 두 개를 보여줍니다. 생애와 이야기에는 기존 캔버스의 글이 모이고, 사진·소리 탭에는 원래 하늘/모아보기를 유지합니다. 추모글에는 롤링페이퍼가 있습니다. 탭은 좌우 화살표와 Home/End로 이동할 수 있습니다.

ForeverMissed는 사용자 지정 참고 대상이지만 현 환경에서 홈페이지 요청이 프록시 403으로 차단되어 최신 화면을 직접 확인하지 못했습니다. 위 구성은 일반적인 추모 페이지 정보 구조를 적용한 것이며 해당 사이트의 현재 화면을 그대로 재현한 것은 아닙니다.

## 사용자 제공 ForeverMissed 스크린샷 반영

실제 사이트의 최신 페이지 대신 사용자가 제공한 스크린샷을 직접 기준으로 삼았습니다. 데스크톱에서 넓은 밤하늘 배너 위 이름과 오른쪽 대표 사진, 바로 아래 내용 메뉴, 본문과 초대/추모글 사이드바의 구성을 적용했습니다. 원본 밤하늘·글꼴·캔버스의 스타일과 기능은 유지합니다. 스크린샷의 풍경·인물 사진·녹색 테마는 복사하지 않았습니다.

대표 사진은 5MB 이하 JPG·PNG·WebP 파일을 검증·디코딩한 뒤 표시하며 세션 중에만 유지됩니다. 초대는 시뮬레이션임을 표시합니다. 사이드바 추모글 버튼은 작성 창으로 직접 연결합니다. 모바일 추가 작업은 하지 않았습니다.

## 웹사이트 게시 — GitHub Pages

`npm run build`로 자체 실행 가능한 `docs/index.html`과 `.nojekyll`을 생성합니다. 서버 없이 정적 호스팅에서 실행되며 입력한 사용자 데이터는 여전히 방문자의 브라우저에만 보관됩니다. 소스를 변경하면 빌드를 다시 실행해야 합니다.

GitHub 저장소의 Settings → Pages → Build and deployment에서 Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/docs**로 지정하고 Save합니다. 게시 후 GitHub가 표시하는 사이트 주소로 접속합니다. 브랜치 푸시만으로 Pages 활성화가 완료되는 것은 아닙니다.

이 환경에서는 GitHub API 요청이 Forbidden으로 거절되어 Pages 활성화를 직접 수행하지 못했습니다. Git HTTPS 업로드와 Pages 사이트 운영은 별개의 권한입니다.
